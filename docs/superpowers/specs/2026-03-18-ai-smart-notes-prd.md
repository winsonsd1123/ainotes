# AI 智能笔记应用 - 产品需求文档（PRD）

> **项目性质：** Vibe Coding 教学演示项目
> **目标受众：** 有一定编程经验的学生
> **教学场景：** 分阶段教学（需求 → 设计 → 编码 → 测试）
> **文档阅读者：** AI 辅助开发工具（Cursor、Claude、Windsurf 等）

---

## 一：全局上下文与架构约束

- **前端框架：** Next.js 14 (App Router) + Tailwind CSS + Shadcn UI
- **后端框架与数据库：** Supabase (PostgreSQL + Auth + Row Level Security) + Server Actions
- **AI 服务：** OpenAI API (GPT-4o-mini) 或 Anthropic Claude API
- **部署平台：** Vercel
- **强制规范：**
  - 所有数据操作必须通过 Server Actions，禁止客户端直接调用 Supabase
  - 所有页面默认使用 Server Components，仅在需要交互时使用 Client Components
  - API 密钥通过环境变量管理，禁止暴露到客户端
  - 所有需要认证的路由必须通过 middleware 进行权限检查
  - AI 调用必须添加超时控制和错误处理
  - 禁止使用散文式的长句，使用短句、无序列表、表格和结构化的逻辑步骤

## 二：核心功能（MVP功能）与操作流程

### 模块 1：用户管理

#### 核心功能 1.1：用户认证与管理（注册/登录/登出）

- **用户故事：** 作为一名 **访客**，我希望能够 **注册账号并登录**，以便于 **拥有专属的笔记空间并使用 AI 功能**。
- **页面交互与执行步骤：**
  1. 用户进入 `/login` 路由页面。
  2. 页面展示登录表单（邮箱、密码）和"去注册"链接。
  3. **注册流程：** 用户在 `/register` 填写邮箱和密码，点击注册。调用 Supabase Auth 接口创建账号，成功后重定向至 `/notes`。
  4. **登录流程：** 用户在 `/login` 填写邮箱和密码，点击登录。调用 Supabase Auth 验证，成功后重定向至 `/notes` 列表页。
  5. **登出流程：** 已登录用户在任意页面（如导航栏）点击"退出登录"按钮，调用 Server Action 清除 Session，并重定向至 `/login`。
  6. **异常反馈：** 邮箱格式错误、密码过短、账号或密码错误时，前端提示具体的错误信息。

### 模块 2：笔记管理

#### 核心功能 2.1：创建笔记

- **用户故事：** 作为一名 **已登录用户**，我希望能够 **创建新笔记并输入内容**，以便于 **记录我的学习笔记并让 AI 帮我生成摘要**。
- **页面交互与执行步骤：**
  1. 用户进入 `/notes/new` 路由页面。
  2. 页面展示表单，包含：标题（文本输入框，必填）、内容（多行文本域，必填）。
  3. 用户填写标题和内容。
  4. 用户点击"保存笔记"按钮。
  5. **前端校验：** 拦截标题或内容为空的提交，显示错误提示。
  6. **数据操作：** 调用 Server Action `createNote()`，向 `notes` 表插入一条记录，关联当前用户的 `user_id`，初始状态为 `DRAFT`。
  7. **AI 处理：** Server Action 在保存成功后，异步调用 LLM API 生成摘要。
  8. **页面反馈：** 保存成功后，全局 Toast 提示"笔记已保存，AI 正在生成摘要..."，并重定向至 `/notes/[id]` 详情页。

#### 核心功能 2.2：查看和管理笔记列表

- **用户故事：** 作为一名 **已登录用户**，我希望能够 **查看我所有的笔记列表**，以便于 **管理和浏览我的笔记**。
- **页面交互与执行步骤：**
  1. 用户进入 `/notes` 路由页面。
  2. **数据获取：** Server Component 从 Supabase 查询当前用户的所有笔记，按创建时间倒序排列。
  3. **列表展示：** 页面展示笔记卡片列表，每个卡片显示：标题、摘要（如果已生成）、创建时间、状态标签。
  4. **交互操作：** 每个卡片包含"查看详情"和"删除"按钮。
  5. **查看详情：** 点击"查看详情"跳转至 `/notes/[id]`。
  6. **删除笔记：** 点击"删除"按钮弹出确认对话框，确认后调用 Server Action `deleteNote()` 删除笔记，并刷新列表。

### 模块 3：AI 功能辅助

#### 核心功能 3.1：AI 生成笔记摘要

- **用户故事：** 作为一名 **已创建笔记的用户**，我希望能够 **让 AI 自动为我的笔记生成摘要**，以便于 **快速了解笔记要点**。
- **页面交互与执行步骤：**
  1. 用户在笔记详情页 `/notes/[id]` 查看刚创建的笔记。
  2. 笔记详情页显示：标题、内容、创建时间、摘要区域（初始状态显示"AI 正在生成摘要..."）。
  3. **后台处理：** Server Action `generateSummary()` 被触发（创建笔记后自动触发或手动点击"重新生成"按钮）。
  4. **AI 调用：** 调用 LLM API，发送用户输入的笔记内容，要求生成 100 字以内的中文摘要。
  5. **数据更新：** AI 返回摘要后，更新 `notes` 表的 `summary` 字段，状态改为 `COMPLETED`。
  6. **页面反馈：** 笔记详情页自动刷新（或通过 revalidatePath），显示生成的摘要。

## 四：核心状态机

**目标对象：** 笔记状态 (`notes.status`)

- `DRAFT` (草稿):
  - **触发条件：** 用户创建新笔记时
  - **允许操作：** 编辑、删除、请求 AI 生成摘要
  - **业务含义：** 笔记已保存，但摘要尚未生成或生成失败

- `COMPLETED` (已完成):
  - **触发条件：** AI 成功生成摘要并保存到数据库
  - **允许操作：** 编辑、删除、重新生成摘要
  - **业务含义：** 笔记和摘要都已完整生成
  - **状态回退：** 用户重新生成摘要时，可临时回退到 `DRAFT`

## 五：防御性边界与异常流

## 5.1 权限与越权防御

- **未登录访问拦截：** 当未登录用户尝试访问 `/notes/*` 任意路由时，middleware 必须拦截并重定向至 `/login`，且携带 `redirectUrl` 参数以便登录后返回原页面。
- **笔记所有权验证：**
  - 查看笔记详情时，Server Action 必须验证 `note.user_id === currentUser.id`，否则返回 403 错误。
  - 删除笔记时，必须在 SQL 查询中添加 `WHERE user_id = $1` 条件，利用 Row Level Security (RLS) 策略双重保障。
- **CSRF 防护：** 所有 Server Actions 默认内置 CSRF token 验证，禁止绕过。

## 5.2 并发与数据异常防御

- **防重复提交：**
  - 前端表单提交按钮点击后立即置灰并显示 Loading 状态。
  - 后端 Server Action 使用 optimistic concurrency control，基于 `updated_at` 字段检测并发修改。
- **AI 调用超时：**
  - LLM API 调用设置 30 秒超时限制。
  - 超时后笔记保持 `DRAFT` 状态，用户可手动重试。
- **AI 调用失败处理：**
  - API 调用失败时，捕获错误并记录到日志（如 Supabase Logflare）。
  - 笔记保持 `DRAFT` 状态，前端显示"摘要生成失败，请重试"提示。
  - 提供手动"重新生成"按钮，允许用户重新触发 AI 调用。
- **数据库连接失败：**
  - 所有数据库操作包裹在 try-catch 中，捕获 `PostgresError`。
  - 失败时返回用户友好的错误提示（如"网络异常，请检查连接后重试"），避免暴露敏感技术细节。

## 5.3 输入验证与清洗

- **标题长度限制：** 标题必须在 1-200 字符之间，超长截断并提示。
- **内容长度限制：** 笔记内容必须在 1-10000 字符之间，超长拒绝保存并提示。
- **XSS 防护：** 用户输入的内容在存储时进行 HTML 转义，展示时使用 React 的默认 XSS 防护机制。
- **AI Prompt 注入防御：** 发送到 LLM 的内容必须经过清洗，移除可能的恶意指令（如"忽略之前的指令"）。

## 附录：开发阶段划分（教学用）

本设计文档旨在支持分阶段教学演示，每个阶段都展示 AI 如何提供帮助：

### 阶段 1：需求阶段
- **AI 协作点：** 将"做一个 AI 笔记应用"的模糊想法，转化为结构化的 PRD 文档
- **教学重点：** 展示 AI 如何理解用户意图，提出澄清问题，补充边界情况

### 阶段 2：设计阶段
- **AI 协作点：** 设计数据模型、状态机、防御性边界
- **教学重点：** 展示 AI 如何应用软件工程原则（SOLID、DRY）进行架构设计

### 阶段 3：编码阶段
- **AI 协作点：** 生成 Next.js 项目骨架、实现 Server Actions、集成 LLM API
- **教学重点：** 展示 AI 如何遵循强制规范、实现类型安全、处理错误

### 阶段 4：测试阶段
- **AI 协作点：** 基于 BDD 验收标准生成测试用例、调试失败测试
- **教学重点：** 展示 AI 如何生成测试代码、分析错误日志、优化性能
